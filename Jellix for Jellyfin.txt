Sticky unbedingt mit Debounce
Das ist bei deiner Anforderung besonders wichtig.
Angenommen 20 Leute schreiben gleichzeitig im Channel.
Nicht:
User schreibt → löschen → posten
User schreibt → löschen → posten
User schreibt → löschen → posten
User schreibt → löschen → posten
Das kann sehr schnell unnötig viele Discord-Requests erzeugen.
Besser:
Message
Message
Message
Message
↓
2 Sekunden Ruhe
Sticky einmal neu posten
Also beispielsweise:
Sticky Debounce: 2 Sekunden
einstellbar zwischen beispielsweise 1–10 Sekunden.
Damit ist die Sticky-Nachricht nach einer Nachrichtenserie wieder unten, ohne für jede einzelne Nachricht Delete + Create auszuführen.
Discord hat sowohl globale als auch routenspezifische Rate Limits und empfiehlt ausdrücklich, Limits nicht fest einzuprogrammieren, sondern die gelieferten Rate-Limit-Header und bei HTTP 429 retry_after zu beachten.

wartet die Queue exakt entsprechend.

Sticky sollte immer niedrige Priorität haben.
Ein /password-reset darf nicht warten, nur weil der Bot gerade 30 Sticky-Nachrichten aktualisieren will.
